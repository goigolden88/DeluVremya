### Сессии Claude Code

Запускать из корня репозитория: история бесед привязана к рабочей папке. Между этапами — `/clear`, `/compact` — для середины этапа. Перед `/clear`: дерево чистое, всё запушено, и по одному Журналу понятно, где мы и что дальше.

### Другие репозитории семьи — только читать

Из «Дневников», «Трапезы», «Злотых» и `FamilyCore` отсюда ничего не правится и не коммитится, даже найденная ошибка: о ней говорится человеку. Сравнение копий — через `git show` объектов git, не по файлам с диска: рабочие копии развёрнуты в CRLF и врут. До 24.09.2026 ядро было копией «Дневников» с `a913dcb`, взятой `git archive` байт в байт (Р-11, Р-15); с переводом на ядро эталон один — `FamilyCore` (Р-83).

### Подмодуль ядра

Действует с 24.09.2026: «Делу Время» переведено на `FamilyCore` коммитом-переездом (Р-83).

- **Клон** — только `git clone --recurse-submodules`; уже склонированное без него — `git submodule update --init`. Иначе `src/shared` пустая и сборка падает непонятной ошибкой
- **`src/shared` отсюда не правится.** Ядру чего-то не хватает, в нём ошибка или `db` и `sync` не подходят под его типы без `as` — сказать человеку, что и где, дать промпт сессии сопровождения `FamilyCore` (шаблон — в её `06-Процесс`) и остановиться. Правка — сессией из корня `FamilyCore`, решением Я-NN, с тестом на «Полке» и зелёным CI ядра
- **Обновление ядра здесь** — `git submodule update --remote src/shared` (или `git -C src/shared checkout <коммит>`), затем `npm test`, `npm run build`, `npm run smoke` по коду выхода и **коммит указателя**. Забытый указатель — правки нет ни у второго устройства, ни в сборке. Видимое человеку изменение ядра — строка в `src/changes.ts` в том же коммите
- **Перед пушем** — `git status` чистый **и в подмодуле тоже**: `git -C src/shared status`
- **В `src/shared` не запускать `npm install`** — заведётся `src/shared/node_modules` со второй копией React (Я-02 «FamilyCore»)
- **Тесты ядра здесь не гоняются, типы — проверяются** (Р-84): `npm test` — только свои; `tsc` в `npm run build` проверяет `src/shared` целиком. Число тестов с 24.09.2026 — 449, а не 722: механика ушла с ядром
- **Откат** перевода — `git revert` коммита-переезда; откат обновления ядра — указатель на прежний коммит, одна строка в диффе. Точка невозврата — первая миграция схемы поверх ядра (Р-83)

## Разделение работы

**Claude Code — и «что строить», и «как».** Продуктовые развилки и пересмотры архитектуры — тоже здесь: он видит настоящие файлы и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой**, для свободного разговора без кода и для картинок. Его итог приходит в репозиторий потоком ниже.

### Планирование в Claude Code

1. Сессия планирования из корня репозитория — заготовка в «Шаблонах»
2. Решения — в `05-Решения` в момент выбора; правки `01`, `02`, `03` — по ходу
3. Конец: Журнал, передача, коммит документов, дерево чистое
4. `/clear` — и код новой сессией по плану. Контекст планирования в неё не переезжает: память — документы

## Поток изменений из чата: чат → документы → код

1. Обсуждаем крупное изменение в чате
2. На выходе — готовые куски markdown для вставки: запись в `05-Решения`, правки `01-Проект` и `02-Архитектура`
3. Отдельным пунктом — что придётся переделать в уже написанном коде
4. Вставляем, коммитим
5. Следующая сессия Claude Code начинается со сверки

## Обратный поток: код → чат

То, что Claude Code в конце сессии называет «не описано в документах», возвращается в обсуждение, а не решается на месте.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test`, `npm run build`, `npm run smoke`**, итог по коду выхода, а не по выводу
- **Прогон проверяется порчей кода**, когда меняется его сценарий: сломанная строка экрана обязана дать код 1
- **Порча — в отдельной рабочей копии, а не в основной папке.** `git worktree add ../DeluVremya-spoil HEAD`, затем `git -C ../DeluVremya-spoil submodule update --init`; `node_modules` — переходом на основные (`mklink /J` из PowerShell), чтобы не ставить зависимости второй раз; порча и прогон — там; после — **сперва снять переход** (`rmdir`, не удаление содержимого), потом `git worktree remove --force ../DeluVremya-spoil`. Основная папка, откуда коммитят, порчи не видит никогда: обрыв сессии посреди порчи её там не оставит. Человек, 14.09.2026: «ок, если это не сильно увеличит расход токенов» — команд на две больше, сборка в копии токенов не тратит. Проверяется при первой порче
- **Видимое изменение — строка в `src/changes.ts`** в том же коммите
- **План содержит только предстоящее**
