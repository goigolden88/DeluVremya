# Процесс

Обновлён: 13.09.2026

Как ведётся работа над проектом. Не про то, что строим, а про то, как.

## Где что живёт

| Что | Где |
|---|---|
| Код приложения | `github.com/goigolden88/DeluVremya`, публичный; сайт — `goigolden88.github.io/DeluVremya/` |
| Документы проекта | `docs/` в том же репозитории |
| Инструкции для Claude Code | `CLAUDE.md` в корне репозитория |
| Данные пользователя | IndexedDB на устройстве; с Этапа 2 — отдельный приватный репозиторий данных |
| Эталон ядра | «Дневники», `github.com/goigolden88/Dnevniki` и локальная копия — **только для чтения** |

Документы лежат вместе с кодом: `CLAUDE.md` подхватывается автоматически, а документы версионируются заодно с кодом. Копия в проекте claude.ai — снимок; правится только репозиторий.

### Сессии Claude Code

Запускать из корня репозитория: история бесед привязана к рабочей папке. Между этапами — `/clear`, `/compact` — для середины этапа. Перед `/clear`: дерево чистое, всё запушено, и по одному Журналу понятно, где мы и что дальше.

### «Дневники» — только читать

Из их репозитория ничего не правится и не коммитится, даже найденная ошибка: о ней говорится человеку. Код оттуда берётся с конкретного коммита через `git archive` — байт в байт, не по памяти и не из рабочей папки. Сначала отдельным коммитом как есть, следующим — правки по делу этого проекта: так дифф второго коммита и есть всё расхождение (Р-11, Р-15).

## Разделение работы

**Claude Code — и «что строить», и «как».** Продуктовые развилки и пересмотры архитектуры — тоже здесь: он видит настоящие файлы и проверяет факты. Режим планирования — когда обсуждаем и ничего не трогаем.

**Чат (Claude Desktop, claude.ai) — когда компьютера нет под рукой**, для свободного разговора без кода и для картинок. Его итог приходит в репозиторий потоком ниже.

### Планирование в Claude Code

1. Сессия планирования из корня репозитория — заготовка в «Шаблонах»
2. Решения — в `05-Решения` в момент выбора; правки `01`, `02`, `03` — по ходу
3. Конец: Журнал, передача, коммит документов, дерево чистое
4. `/clear` — и код новой сессией по плану. Контекст планирования в неё не переезжает: память — документы

## Поток изменений из чата: чат → документы → код

1. Обсуждаем крупное изменение в чате
2. На выходе — готовые куски markdown для вставки: запись в `05-Решения`, правки `01-Проект` и `02-Архитектура`
3. Отдельным пунктом — что придётся переделать в уже написанном коде
4. Вставляем, коммитим
5. Следующая сессия Claude Code начинается со сверки

## Обратный поток: код → чат

То, что Claude Code в конце сессии называет «не описано в документах», возвращается в обсуждение, а не решается на месте.

## Правила ведения документов

- **Не менять задним числом.** Отмена решения — новая запись со ссылкой
- **Решения записываются в момент выбора**
- **Журнал обновляется в конце каждой сессии**
- **Перед пушем — `npm test`, `npm run build`, `npm run smoke`**, итог по коду выхода, а не по выводу
- **Прогон проверяется порчей кода**, когда меняется его сценарий: сломанная строка экрана обязана дать код 1
- **Видимое изменение — строка в `src/changes.ts`** в том же коммите
- **План содержит только предстоящее**

## Шаблоны

Начало сессии по плану:

```
Работаем по docs/03-План.md, следующий этап оттуда.
Прочитай CLAUDE.md и docs/ перед началом.
Сначала покажи план работ, код пиши после подтверждения.
```

Сессия планирования:

```
Планируем: <что — новый этап, модуль, развилка>. Прочитай CLAUDE.md
и docs/. Код не пишем — обсуждаем по одной развилке, с твоей
рекомендацией, и записываем решения в docs/ в момент выбора.
В конце — Журнал, передача в 06-Процесс, коммит документов.
```

Начало сессии после обновления документов в чате:

```
Я обновил docs/. Прочитай их и сверься с кодом.
Скажи, что теперь расходится и в каком порядке это править.
```

Конец сессии:

```
Дай текст для docs/04-Журнал.md: что сделано, в каком состоянии,
следующий шаг. И для docs/05-Решения.md, если по ходу что-то решили.
Отдельно — что осталось не описанным в документах.
```
