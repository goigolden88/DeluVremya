# Архитектура

Обновлён: 13.09.2026
Версия схемы данных: 1

## Стек

- **Vite + React + TypeScript**, `strict` и `noUncheckedIndexedAccess`. Проект идёт через много сессий, и без типов модель расползётся между ними
- Роутинг через хеш (`#/today`), библиотека `react-router-dom`, `HashRouter` — на GitHub Pages обычные пути дают 404 при обновлении страницы
- Сайт живёт по `/DeluVremya/`, а не в корне домена: `base` в `vite.config.ts` равен имени репозитория. С ним же согласованы `start_url`, `scope`, `id` манифеста и пути иконок. Неверный `base` даёт зелёную сборку и белую страницу — диагностируется плохо, лечится одной строкой
- Стили обычным CSS, без Tailwind
- Хранилище на устройстве — IndexedDB
- Service worker свой, `src/sw.ts`, собирается `injectManifest` — иначе в него не положить код напоминаний
- В манифесте **`share_target` и `shortcuts`** (Р-09). Это не украшение, а главный путь ввода
- Бэкенда нет

## Два репозитория

| Репозиторий | Что внутри | Видимость |
|---|---|---|
| `DeluVremya` | исходники, сборка, GitHub Pages | публичный |
| Данные | JSON-файлы с записями | приватный |

Pages для приватного репозитория требуют платного тарифа, поэтому код публичный. Секретов в нём нет по определению. Токен вводится руками в настройках и живёт только в браузере.

## Модель данных

Две категории сущностей: **справочники** (чем пользуемся) и **записи** (что было или задумано).

### Общая часть

```ts
type Base = {
  id: string          // ULID, генерируется локально, сортируется по времени
  updatedAt: string   // ISO 8601, время последнего изменения записи
  deleted?: boolean   // метка удаления, не вычищается никогда
}
```

Та же `Base`, что в «Дневниках» и в будущих приложениях семьи — чтобы позже слить ленты без переделок.

### Справочники

```ts
// Категория учёта времени: Зарядка, Шахматы, Чтение, Ютуб, Прогулка, Прочее…
type Category = Base & {
  name: string
  order: number                // порядок на экране дня и в сводках
  kind: 'useful' | 'neutral' | 'idle'   // признак для обзора недели, не для дневного экрана (Р-05)
  archived?: boolean
}

// Пресет — кнопка «Чтение +30». Заводится с экрана категории.
type Preset = Base & {
  categoryId: string
  minutes: number
  order: number
}

// Шаблон дня: «рабочий», «выходной». Порождает записи плана на конкретный день.
type DayTemplate = Base & {
  name: string
  items: { title: string; estMin?: number; main?: boolean }[]
  order: number
}
```

### Записи

```ts
// Одна сущность на входящее, дело, наблюдение и пункт плана дня (Р-09).
type Note = Base & {
  text: string
  kind: NoteKind               // 'task' | 'thought'
  capturedOn: string | null    // YYYY-MM-DD, когда записана; null → дата неизвестна (Р-08)
  plannedFor: string | null    // YYYY-MM-DD, на какой день поставлена; null → лежит во входящих
  main?: boolean               // главное дело того дня, на который поставлена
  estMin?: number              // оценка длительности, для реализма плана
  status: NoteStatus           // 'open' | 'done' | 'someday' | 'dropped'
  doneOn?: string              // YYYY-MM-DD, когда выполнено
  refs?: string[]
}

type NoteKind = 'task' | 'thought'
type NoteStatus = 'open' | 'done' | 'someday' | 'dropped'

// Блок учтённого времени.
type TimeBlock = Base & {
  date: string                 // YYYY-MM-DD, дата события, не дата ввода
  categoryId: string
  minutes: number
  bgCategoryId?: string        // фоновая активность: покер под ютуб
  note?: string
  refs?: string[]
}

// Проведённый обзор недели.
type Review = Base & {
  weekStart: string            // YYYY-MM-DD, понедельник недели
  doneAt: string               // ISO 8601, когда обзор провели
  note?: string
  refs?: string[]
}

// Вид записи. Три значения — ровно то, что описано выше.
type RecordKind = 'note' | 'time' | 'review'
```

### Заметки по модели

- **Входящее, дело, наблюдение и пункт плана — одна структура** (Р-09). Входящее — `plannedFor: null`; пункт плана — дата проставлена; наблюдение — `kind: 'thought'`. Переход между состояниями это правка двух полей, а не превращение одной сущности в другую
- **`capturedOn` и `plannedFor` — разные вещи.** Первое отвечает на «когда записана» и кормит возврат наблюдений, второе — на «на какой день поставлена». Мысль, записанная в марте и поднятая в плане в июне, сохраняет оба
- **`estMin` необязательна.** Реализм плана считается по тем пунктам, у которых она есть, и всегда называет, сколько пунктов в счёт не вошло. Число идёт с основанием
- **Привычки своей сущности не имеют** (Р-03). Шаблон дня порождает обычные `Note` на конкретный день; выполнение привычки — обычный `status: 'done'`
- **Фоновая активность — поле, а не вторая запись.** Одна запись описывает «час ютуба, под него покер»; сумма по основной категории не удваивается
- **`refs` зарезервировано** под связи между записями и, позже, между приложениями семьи. Сейчас не используется
- **`kind` категории существует, но на дневном экране не красит** (Р-05). Признак нужен обзору недели, где смотрят на неделю целиком

## Раскладка данных в репозитории

```
meta.json                 { schemaVersion }
categories.json           категории учёта времени
presets.json              кнопки быстрого ввода
templates.json            шаблоны дня
notes/2026.json           записи за год
notes/undated.json        записи без разбираемой даты (Р-08)
time/2026.json            блоки времени за год
reviews.json              обзоры недель
```

Год записи `Note` берётся по `capturedOn`; если её нет — запись уезжает в `notes/undated.json`. Туда же попадает запись с испорченной датой: терять её из-за одной кривой строки нельзя.

Нарезка по годам нужна git: без неё каждая отметка времени переписывала бы всю базу и раздувала историю коммитов. Прошлые годы после закрытия не переписываются.

Раскладка описана таблицей в `core/layout.ts` — единственное место, где она известна.

## Синхронизация

**Принцип: local-first.** Запись сохраняется на устройстве и отражается на экране до всякой сети. Синхронизация — фоновый процесс, который может отставать или падать, не ломая работу.

Механика берётся из «Дневников» целиком и без изменений (Р-11):

1. Запись падает в IndexedDB, экран обновляется мгновенно
2. Изменённые записи помечаются грязными — это признак «есть что отправлять», а не список файлов
3. Через пять секунд после последнего действия — проход. Также при открытии, при возврате вкладки из фона и при возврате сети
4. Читаем голову ветки и дерево файлов — два запроса. Скачиваем только файлы с разошедшимся отпечатком
5. Сливаем в базу, пересобираем дерево из базы целиком, отправляем разошедшиеся **одним коммитом**
6. Ветка ушла вперёд → пауза, перечитать, слить заново. Три попытки, потом откладываем на минуту
7. **Сначала влить чужое, потом отправить своё.** Любая ошибка чтения обрывает проход до записи

Репозиторий без единого коммита Git Data API не обслуживает: первый файл кладётся через Contents API.

### Правило слияния

**Для каждой записи по `id` побеждает версия с более поздним `updatedAt`.** По записи, а не по файлу целиком — иначе запись с телефона затрёт запись с компьютера. Удалённые остаются надгробиями навсегда: вычистишь — второе устройство воскресит.

### Файл-копия

Кнопкой в «Настройках» скачивается один файл-слепок, а не раскладка выше:

```
{ schemaVersion, exportedAt, data: { <хранилище>: [записи] } }
```

Все синхронизируемые хранилища вместе с надгробиями. `settings` не входит — там токен. Загрузка сливается общим правилом. Форма проверяется до записи, файл чужой схемы отвергается целиком.

Делимся `.txt` с тем же содержимым: Chrome на Android не отдаёт `.json` в системное «Поделиться».

### Импорт записей

Второй вход, для чужих записей — заметок Obsidian, февральской таблицы, выгрузок (Р-08). Слепок сюда не принимается, у него свой вход.

```
{ "format": "deluvremya-import", "version": 1,
  "notes": [...], "time": [...] }
```

Без `id` и `updatedAt`, ссылки по названиям: категория ищется по имени без учёта регистра, недостающая заводится.

- **Дата необязательна.** Запись без даты принимается, уезжает в `notes/undated.json`, видна в списке и в поиске — но в возврат наблюдений не попадает: показывать «месяц назад» нечего
- Каждое поле проверяется; кривая запись в базу не попадает и называется с причиной
- До записи — сводка: что добавится, что уже есть, что не разобрано. Пишется только по кнопке
- **Только добавляет.** Совпавшее по естественному ключу пропускается. Ключи: заметка — текст и `capturedOn`; блок времени — категория, дата и минуты
- JSON принимается и в блоке ` ```json ` с текстом вокруг — так его отдаёт ИИ

Поля и пример каждого раздела описаны в `modules/<имя>/import.ts`; из тех же описаний собирается промпт для ИИ, и тест прогоняет примеры из промпта через собственную проверку. Разойтись они не могут.

## Локальное хранилище

IndexedDB, не localStorage: у второго лимит около 5 МБ и синхронный API, который подвесит интерфейс на импорте.

База называется `deluvremya`. Имя обязано отличаться от `dnevniki`: оба приложения живут на одном origin `goigolden88.github.io`, а IndexedDB общая на origin и различается только именем. Кеши service worker разведены сами — workbox вписывает scope в имя кеша и чистит только свой.

Синхронизируемые хранилища — `categories`, `presets`, `templates`, `notes`, `time`, `reviews`: имена совпадают с раскладкой в репозитории. Локальные — `meta`, `settings`, `dirty`. Имена лежат в базе на устройствах и не меняются никогда. Индексы сверх `updatedAt`: у `notes` — `capturedOn` и `plannedFor`, у `time` — `date`, у `reviews` — `weekStart`.

Настройки хранятся отдельно и **не синхронизируются**: в них токен, а «когда я в последний раз синхронизировался» у каждого устройства своё.

| Ключ | Что лежит |
|---|---|
| `syncEnabled` | включена ли синхронизация. По умолчанию нет |
| `syncRepo` | `владелец/репозиторий` данных |
| `syncToken` | fine-grained токен. В выгрузку не попадает никогда |
| `syncBranch` | ветка, по умолчанию `main` |
| `syncTokenExpires` | когда истекает токен |
| `syncLastAt`, `syncLastCommit`, `syncTree` | состояние последнего успешного прохода |
| `lastExportAt` | когда в последний раз забирали копию файлом |
| `reminderWindow` | часы со звуком `{ from, to }`, по умолчанию 12–20 |
| `reminderLastDay`, `reminderQuietDay` | в какой день уже приходило громкое и тихое напоминание |
| `reminderLog` | последние 20 фоновых пробуждений: когда и чем кончилось |
| `folds` | какие блоки экрана свёрнуты |
| `seenChanges` | последняя прочитанная запись «Что нового» |
| `welcomeDone` | приветствие первого запуска закрыли |
| `errorLog` | последние необработанные ошибки страницы — идут в отчёт об ошибке |

**У каждого устройства свой токен.** Телефон настраивается отдельно от компьютера. Токен выпускается прямо на том устройстве, где будет жить: потерянный телефон отзывается одной кнопкой, не ломая компьютер.

## Структура кода

**Продуктовых модулей четыре, кодовых — два** (Р-10). Входящие и план дня работают с одной сущностью и живут в `notes`. Обзор недели читает оба модуля и потому модулем быть не может: он лежит в `screens/`, рядом с `app.tsx`, — иначе нарушил бы правило «модули не знают друг про друга» в первый же день.

Ядро скопировано из «Дневников» с их коммита `a913dcb` (Р-11, Р-15): `db`, `id`, `dates`, `github`, `layout`, `sync`, `sw`, `ui/install`, `ui/backup`, `ui/Fold`, прогон и скрипт иконок. Всё расхождение с ними — дифф коммита «модель «Делу Время» и правки ядра по делу проекта». **Номера Р-NN в комментариях скопированного кода — номера решений «Дневников», а не этого проекта.**

**Правила, которые соблюдаются жёстко:**

- `core` не знает про модули
- Модули не знают друг про друга — только через `refs` и общую ленту
- `ui` не знает про модули; модули пользуются `ui`
- Все модули разом знают только `app.tsx`, `registry.ts`, `notify.ts` и `screens/`
- К хранилищу обращаются только через `db`, напрямую в IndexedDB не ходит никто
- Работа с GitHub спрятана в `core`. Другой git-хостинг — правка `core/github.ts`; хранилище без git — ещё и прохода в `core/sync.ts`
- Логика вне компонентов: расчёт — чистые функции с тестами, экраны тестами не покрываются

## Приём из «Поделиться» и быстрые действия

`share_target` в манифесте — `GET` на корень приложения с параметрами `title`, `text`, `url` (Р-16). Android открывает `/DeluVremya/?text=…`; `src/launch.ts` при старте, до первого экрана, переводит адрес во внутренний `#/inbox?shared=…` и чистит строку адреса. Service worker в приёме не участвует: такую навигацию он и так отдаёт из кеша, а без него её отдаёт GitHub Pages. Ссылка или кусок текста из любого приложения попадают во входящие без открытия экрана вручную — это прямая замена «Избранному» Телеграма. Картинки не принимаются — отложены (Р-16).

`shortcuts` в манифесте дают по долгому тапу на иконке: «Записать» (`?go=inbox`), «План дня» (корень), «Учесть время» (`?go=time`). Вход тот же, `launch.ts`. Адреса ярлыков и `share_target` зашиваются в установленное приложение на Android, поэтому меняются только вместе с обратной совместимостью: старый адрес обязан продолжать работать.

Оба механизма — Android у установленного приложения. На компьютере и во вкладке их нет, и это приемлемо: быстрый захват нужен с телефона.

## Как добавить модуль

1. **`core/model.ts`** — типы записей, имена хранилищ в `SYNCED_STORES`, строки в `StoreRecord`, новое значение в `RecordKind`
2. **`core/db.ts`** — строка в `INDEXES`. Для хранилищ после версии 1 она только держит таблицу полной: индексы заводит миграция
3. **`core/model.ts`** — миграция: поднять `SCHEMA_VERSION`, добавить шаг. Шаг **сам создаёт хранилище и его индексы**; `V1_STORES` не трогается никогда. `additive: true`, если форма прежних записей не меняется. Перед пушем — оба прогона на свежей копии настоящих данных
4. **`modules/<имя>/`** — расчёт, экраны, работа с `db`. Логика модуля живёт здесь, а не в `core`
5. **`core/layout.ts`** — строка в `PLACES`: одним файлом или нарезкой по годам, и по какой дате берётся год
6. **`app.tsx`** — маршрут, при необходимости вкладка
7. **`src/registry.ts`** — строка на вид записи: подпись, строки ленты, раздел markdown, раздел импорта. Компилятор не соберёт приложение, пока строки нет

Чего делать **не** нужно: править `db`, сам проход синхронизации или соседний модуль. Понадобилось — граница нарушена, и это повод остановиться.

## Реестр видов записей

Общая лента и выгрузка в markdown — единственные места, где модули встречаются по данным. Реестр — таблица `{ [K in RecordKind]: … }` в `src/registry.ts`. Тип проверяется компилятором на полноту: забыть вид нельзя.

Маршруты, вкладки и блоки «Сегодня» через реестр не идут — это продуктовые решения, из списка они не выводятся.

## Версионирование схемы

`meta.json` содержит `schemaVersion`. Заводится с первого дня, миграции пишутся сразу: свежая база доезжает до текущей версии теми же шагами, что и база установленной копии. Отставание схемы само по себе не отвергает файл-копию — только если между версиями есть шаг с `additive: false`.

## Известные слабые места

| Риск | Смягчение |
|---|---|
| Токен лежит в браузере открытым текстом | fine-grained на один репозиторий, только содержимое; свой на устройство |
| Токен протухает | срок виден в «Настройках», предупреждение заранее, отдельный текст ошибки |
